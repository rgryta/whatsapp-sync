# Working in this repo

## Gates — all clean before every commit

```bash
cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --release --workspace --bins
```

```
crates/client    our own WhatsApp linked device and the ingester: adopts WAHA's Baileys
                 session, decrypts pairwise (src/signal: libsignal v0.74.1's version-3 path,
                 vendored because later releases removed X3DH) and group messages, archives,
                 transcribes voice notes. AGPL-3.0-only like libsignal; nothing MIT may
                 depend on it
crates/core      row types, db, config, store (every SQL statement)
crates/mcp       the read surface
src/bin/         `whatsapp-mcp`, in the root package, which must never gain a
                 `whatsapp-client` dependency
```

`crates/client/tests/fixtures/` is regenerated by the `scripts/*.mjs` generators, which run
inside WAHA's image so every fixture is written by the same Baileys WAHA ran.

The tests share one named, reusable `postgres:18-alpine` container
(`whatsapp-sync-test-pg`) and build their own DSN. Never set `DATABASE_URL`: the queries are
runtime-checked on purpose, so the build is hermetic and nothing can point at a real
database. Remove the container with `docker rm -f whatsapp-sync-test-pg`.

No test touches WhatsApp or a real database. **Never point the suite at
`homelab-postgres`** — the archive is the product, and a suite that can TRUNCATE it
is a loaded gun left on the table.

## Commits

- Two lines maximum. No co-author trailers. No emojis.
- Subject line says what changed; the second line says why, if it is not obvious.

## Deployment

**Agents do not deploy.** Agents build and push images; a human deploys in Dockge.
When telling the user to deploy, say **Update** (which pulls the new image), never
Restart — Restart reuses the image already on disk and the change silently does not
land.

`.github/workflows/tag.yml` and `image.yml` can build a tagged release on GitHub and push it to
ghcr, as the-act-of-complexio does, but they are disabled: images are built by hand on the NAS
and pushed to the local registry. `ci.yml` runs the gates on every pull request.

`/homelab_stack/*` is the live stack and is read-only to agents.

## Secrets

- `.env` files committed to this repo carry variable **names with empty values**.
  Never copy a real secret into the repo.
- No real person's name, number, LID, group or message goes into a fixture or test: make
  them up.

## Invariants worth not breaking

- **Two processes, unequal rights.** `whatsapp-client` owns the schema and is the only
  thing that applies migrations or writes messages. `whatsapp-mcp` reads, asserts the
  migrations it was built against, and refuses to start on drift. That is a missing
  dependency edge: the root package and `crates/{core,mcp}` must not depend on
  `whatsapp-client`, so the code that can reach WhatsApp is not in the MCP process at all.
  All SQL lives in `crates/core/src/store/`, and `tests/archive/isolation.rs` keeps both
  facts honest.
- **WAHA and `whatsapp-client` are the same WhatsApp device.** Never run both.
- **Migrations are forward-only** and applied in filename order. Never edit an
  applied migration; add another.
- **The device's keys live in schema `device`, never `public`.** `crates/client` keeps the
  linked device's private keys and Signal sessions there, with its own migrations
  (`crates/client/migrations/`) applied by the client alone. `public` is wrong twice over: the
  live database's default privileges grant the MCP role SELECT on every new table there, and
  the MCP's migration assert would tie its deploys to the client's.
  `crates/client/tests/store.rs` proves a role granted like the MCP is refused.
- **Archive, then save the Signal state, then send the receipt.** A crash in between means a
  re-delivery, which the upserts absorb; any other order loses messages.
- **Ordering is `(ts, message_id)` everywhere.** WhatsApp timestamps are whole
  seconds, so `ts` alone ties and paging silently skips or repeats.
- `crates/mcp/src/render.rs` is the only place that decides what reaches the model. `raw`
  never reaches it — but that is a *rendering* rule, not a storage one: storage keeps
  everything.
